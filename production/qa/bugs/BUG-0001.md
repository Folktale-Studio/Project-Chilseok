# BUG-0001: 좌우로 걷다가 점프하면 반대 방향으로 밀린다

**Severity**: S2-High
**Priority**: P1-이번 이슈에서 수정
**Status**: Verified Fixed
- **System**: Player / Puzzle.PlayerMovement
- **Issue**: [#9](https://github.com/Folktale-Studio/Project-Chilseok/issues/9)
- **Frequency**: 항상 (평지에서 칸 사이를 이동하는 중 점프한 재현 조건)
- **Build**: `fe52f15`

## 재현 절차

1. Unity에서 B09 이동 미리보기 코스를 실행한다. 회전 없이 시작 시점 0°를 사용한다.
2. 평평한 발판 위에서 A 또는 D로 이동한다.
3. 다음 칸에 도착하기 전에 방향키를 누른 채 Space를 누른다. 좌우를 각각 확인한다.

## 기대 결과

점프가 시작되어도 수평 위치가 입력 반대 방향으로 되돌아가지 않는다. 착지는 기존의 1칸 높이·틈 허용 규칙을 따른다.

## 실제 결과

이동 중 점프하면 진행 방향의 반대로 밀린다. Unity CLI에서 기본값과 평지 격자로 독립 재현했다. 오른쪽 입력은 수평 위치가 3.400 → 3.388 → 3.000으로 줄었고, 왼쪽 입력은 2.600 → 2.612 → 3.000으로 늘었다. 각 값은 점프 직전, 점프 첫 프레임, 착지 직후다.

## 근거 (파일:줄, 로그, 스크린샷)

- [PlayerMovement.cs:108](../../../Assets/Chilseok/Scripts/Puzzle/PlayerMovement.cs#L108)에서 한 칸 오르기와 틈 건너기에 모두 해당하지 않는 점프의 착지 목표를 마지막으로 확정한 발 칸 `Feet`에 둔다. 칸 사이에서 이미 움직인 화면 위치와 착지 목표가 어긋나면 포물선의 수평 보간이 이전 칸 중심으로 향한다. 재현값과 일치한다. 원인 확신도는 높다.
- 조사 시 Unity 콘솔의 현재 오류와 경고는 0건이었다.

## 수정 제안

점프 진입 시 칸 사이의 실제 위치와 입력 방향을 보존한다. 평지 착지에 쓸 발 위치를 투영 맵에서 결정하고, 좌·우 각각 부분 이동 후 점프의 수평 위치가 역행하지 않는지 회귀 검사한다. 1칸 높이·틈은 넘고 2칸은 넘지 못하는 조건도 같이 검사한다.

## 수정 검증

11/23 회귀 테스트에서 좌우로 칸의 40%와 60%를 움직인 뒤 점프했다. 점프 첫 프레임부터 착지까지 수평 위치는 입력 방향을 유지했다. 방향키를 뗀 뒤 점프한 경우에는 실제 출발 위치에 착지했다. PlayMode 27건과 1칸·2칸 높이 및 틈 제한을 통과했다.
