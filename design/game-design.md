# 칠석(가제) 기획안

Nov 20, 2026 · @기현

## 한 줄 컨셉과 의도

은하수에 가로막힌 견우가 시점을 90°씩 돌려 멀리 떨어진 별들을 한 줄로 이어 붙이며 직녀에게 가는 시점 회전 퍼즐 플랫포머다.

- **메커닉이 곧 테마**: 투영하면 깊이가 사라진다. 그래서 멀리 떨어진 별도 맞는 각도에서 보면 닿는다. 그렇게 이어진 길이 오작교다.
- **비주얼**: 먹색과 한지색 2색 디더링. 목판화 삽화처럼 보이게 한다.
- **포트폴리오 목적**: 솔버가 모든 레벨의 풀이 가능 여부와 난이도를 자동으로 계산한다. 이것으로 AI와 사람의 역할을 나눈 워크플로우를 보여 준다.
- **플랫폼과 분량**: Unity 6 URP, WebGL(itch.io) 빌드, 플레이 10\~15분.

## 플레이 방식

플레이어는 끊김 없는 한 길을 따라 견우의 여정을 걷는다. 길 중간의 별무리 구간에 들어서면 세상을 90° 돌려 새 길을 만들고, 구간 끝의 까치에 닿으면 까치가 다음 구간으로 길을 안내한다.

| 행동 | 키보드 | 패드 |
| --- | --- | --- |
| 이동 | A / D | 왼쪽 스틱 |
| 점프 | Space | 아래 버튼(A) |
| 시점 회전 | Q / E | LB / RB |
| 다시 시작 | R | View |

**한 판의 흐름**

1. 프롤로그 글 카드 한 장 뒤 여정이 시작된다. 이후로는 화면을 끊는 카드가 없다.
2. 구간 사이 길에서는 회전이 잠기고, 걸으면 화면 아래에 내레이션이 한 줄씩 흐른다.
3. 별무리 구간에 들어서면 시점 표시가 켜지고 회전할 수 있다.
4. 까치에 닿으면 오작교 한 칸이 놓이고, 까치가 날아가 다음 구간 방향을 알려 준다.

**실패**: 은하수로 떨어지면 그 구간의 입구로 돌아간다. 구간 입구가 곧 체크포인트이고, 목숨과 시간 제한도 없다.

## 핵심 규칙

구간 하나는 최대 8×8×8 복셀 그리드이고, 시점은 4방향(0·90·180·270°) 직교 카메라다. 규칙은 네 개뿐이다.

1. **투영**: 현재 시점에서 화면의 한 칸(가로, 높이)은 깊이 방향 어느 칸에든 블록이 있으면 단단하다. 플레이어는 이 2D 충돌 맵 위에서만 움직인다.
2. **회전**: 땅에 서 있을 때만 돌 수 있다. 회전하는 0.35초 동안에는 입력을 받지 않는다.
3. **재배치**: 회전해도 화면 위치(가로, 높이)는 그대로다. 깊이는 발밑을 받치는 블록 중 카메라에 가장 가까운 블록의 깊이로 정한다. 받칠 블록이 없으면 떨어진다.
4. **회전 거부**: 새 시점에서 플레이어 자리가 단단한 칸과 겹치면 회전을 취소한다. 화면이 살짝 흔들리고 소리가 난다.

**구간 제한**: 회전과 투영은 플레이어가 서 있는 별무리 구간 안에서만 작동한다. 긴 길 전체를 돌리면 길이 깊이 방향으로 겹쳐 한 열로 무너지기 때문이다.

**이동 능력**

- 걷기: 좌우로 자유롭게 움직인다.
- 점프: 1칸 올라가기, 가로 1칸 틈 건너기. 2칸은 못 넘는다.
- 낙하: 높이 제한이 없고 피해도 없다.

점프를 1칸으로 고정하는 이유는 솔버가 이동을 추상 행동으로 정확히 흉내 낼 수 있게 하기 위해서다. 회전 거부도 같은 이유로, 밀어내기 같은 보정 대신 단순한 규칙을 택했다.

## 구간 구성

여정은 별무리 구간 6개로 이뤄지고, 솔버가 셈 최소 회전 수가 구간마다 늘어나도록 배치한다. 구간마다 새로 배우는 것은 하나뿐이다.

| 구간 | 새로 배우는 것 | 최소 회전 수(목표) |
| --- | --- | --- |
| 1 | 걷기와 점프. 회전 없이 클리어 | 0 |
| 2 | 한 번 돌면 떨어진 별이 붙는다 | 1 |
| 3 | 회전 거부. 돌 수 없는 자리가 있다 | 2 |
| 4 | 떨어지면서 길을 찾는다 | 2\~3 |
| 5 | 같은 방향으로 두 번 돌기, 되돌아가기 | 3\~4 |
| 6 | 종합. 오작교 완성과 엔딩 | 4\~6 |

구간은 한 월드에 이어 붙이고 사이는 회전이 잠긴 평지 길로 잇는다. 구간 데이터는 ScriptableObject로 두고, AI가 초안을 내면 솔버가 검증하고 사람이 고른다.

## 서사와 글 카드

서사는 문장 8개(프롤로그, 구간 6개, 엔딩)로 전한다. 프롤로그와 엔딩만 화면 카드이고, 나머지는 구간 사이 길을 걸을 때 화면 아래에 한 줄씩 흐른다. 아래는 초안이다.

- **프롤로그**: 옛날 옛적, 하늘 강 이쪽에는 소 치는 견우가, 저쪽에는 베 짜는 직녀가 살았더란다. 일 년에 딱 하룻밤, 까치들이 다리를 놓아 주는 날이 있었는데…
- **첫째 구간**: 별들은 멀리 흩어져 있었지. 견우는 우선 발밑부터 살폈단다.
- **둘째 구간**: 아무리 봐도 닿지 않던 별이, 고개를 돌리자 바로 옆에 있더란다.
- **셋째 구간**: 어떤 자리에서는 아무리 고개를 돌려도 하늘이 꿈적도 않았지.
- **넷째 구간**: 때로는 발을 헛디더야 길이 보이는 법이란다.
- **다섯째 구간**: 갔던 길을 되돌아와야 비로소 보이는 별도 있었지.
- **여섯째 구간**: 이제 까치 한 마리만 더 있으면 됐단다.
- **엔딩**: 까치들이 날개를 펴자 하늘 강 위로 다리가 놓였어. 그날 밤 내린 비는 두 사람이 반가워 흘린 눈물이었다지.

견우직녀는 구전 설화라 자유롭게 쓸 수 있다. 문장은 원전을 옮기지 않고 새로 쓴다.

### 도입 시네마틱

약 55초, 건너뛸 수 있다. 컷마다 2D 일러스트 한 장을 전경·중경·배경으로 나눠 패닝하고, 게임과 같은 디더링 셰이더를 통과시켜 화풍을 통일한다. 마지막 컷은 디더 디졸브로 흩어지며 인게임 첫 장면으로 이어진다.

| 컷 | 장면 | 디더 연출 | 범위 |
| --- | --- | --- | --- |
| 1 | 하늘 강 전경. 프롤로그 문장 | 점이 피어나는 페이드, 별 반짝임 | 필수 |
| 2 | 성실하던 시절: 왼쪽에 소를 모는 견우, 오른쪽에 베틀 앞의 직녀 | 양쪽에서 중앙으로 패닝 | 있으면 좋음 |
| 3 | 함께 살던 한때: 중앙에 나란히 앉은 두 사람의 실루엣 | 디더 디졸브 전환 | 있으면 좋음 |
| 4 | 이별: 은하수가 갈라지며 두 사람이 양끝으로 밀려남 | 좁은 강에서 넓은 강으로 디졸브, 먹·한지 반전 | 필수 |
| 5 | 기다림과 징조: 홀로 남은 견우 위로 달이 보름달 → 그믐달 → 달 없는 밤 → 초승달 → 상현달로 바뀜다. 이 순환을 점점 빠르게 2\~3번 돌려 일 년이 흘렀음을 보여 주고, 마지막에 상현달(음력 7일, 칠석)에서 멈춘 뒤 별 하나가 유독 반짝인다 | 달 그림 4장 교체(첫 순환 장당 약 0.5초, 마지막 순환은 장당 약 0.15초), 달 없는 밤은 달 레이어를 끔, 상현달에서 1초 멈춤, 마지막 별 반짝임, 컷 전체에 느린 카메라 밀기 | 추천 |
| 6 | 출발: 까치가 날아오르고 견우가 삿갓을 고쳐 씀 | 디더 디졸브로 인게임 전환 | 필수 |

갈라놓는 존재(옥황상제)는 등장시키지 않고 강이 넓어지는 장면으로만 처리한다. 연출 값(밝기, 디졸브 진행도, 반전, 내부 해상도)은 컷 데이터에서 시간에 따라 바뀐다.

5번 컷의 달이 상현달에서 멈추는 이유: 칠석은 음력 7월 7일이고, 음력 7일 밤의 달은 오른쪽 절반이 빛나는 상현달이다. 보름달은 음력 15일쯤이라 끝을 보름달로 두면 날짜가 맞지 않는다. 보름달로 시작하는 것은 이별 직후의 슬픔을, 달 없는 밤은 기다림이 가장 깊은 때를 뜻한다.

## 아트·사운드 방향

디더링이 스타일을 다 만들어 주므로, 에셋은 기본 도형과 CC0 캐릭터만 쓴다.

- **팔레트**: 먹 #1D1A17, 한지 #E8DFC8 두 색.
- **렌더**: 내부 해상도 480×270으로 그린 뒤 확대한다. 밝기에 Bayer 4×4 순서 디더링을 거는 URP Renderer Feature 풀스크린 패스다.
- **캐릭터**: 컨셉 아트를 그린 뒤 이미지 기반 3D 생성으로 견우와 직녀를 만든다. 3시간 안에 쓸 만한 결과가 없으면 Quaternius Universal Base Characters로 대체한다. 애니메이션은 Universal Animation Library의 대기·걷기·점프·낙하. 한복 느낌은 머리 모양과 갓 같은 큐브 소품으로 낸다.
- **블록과 배경**: 블록은 큐브에 노이즈 텍스처, 별은 발광 구체, 은하수는 바닥 아래 파티클.
- **회전 연출**: 0.35초 이징 회전. 디더 패턴이 지글거리는 시간을 이만큼으로 제한한다.
- **폰트**: 나눔명조 또는 고운바탕(OFL).
- **사운드(선택)**: 회전, 착지, 까치 울음만. Freesound의 CC0 소리.

외부 에셋과 AI로 만든 에셋은 `CREDITS.md`에 출처와 라이선스를 적는다.

### 뽑을 이미지

약 20장이다. 16:9, 1920×1080 이상, 디더링 없는 흑백으로 뽑고, 참조 이미지(고른 캐릭터 디자인, 5번 컷 화풍)를 항상 첨부한다. 움직임용 추가 그림은 새로 뽑지 않고 원본을 이미지 편집으로 고친다. **(필수)** 표시만 있어도 필수 시네마틱 3컷과 게임 진행이 된다.

**A. 캐릭터 기준 (가장 먼저)**

- [ ] A1 견우 디자인 3\~4장 중 1장 고르기 (3/4 시점) **(필수)**
- [ ] A2 직녀 디자인 3\~4장 중 1장 고르기
- [ ] A3 견우 정면 A포즈 전신, 3D 변환용 **(필수)**
- [ ] A4 직녀 정면 A포즈 전신, 3D 변환용 (엔딩)

**B. 도입 시네마틱**

- [ ] B1 하늘 강 전경 **(필수)**
- [ ] B2 성실하던 시절, 2:1 파노라마로 넓게
- [ ] B3 함께 살던 한때 실루엣
- [ ] B4 이별: 좁은 강 본 그림 + 넓은 강 편집본 **(필수)**
- [x] B5 기다림: 하늘을 향해 손을 뻗는 견우 본 그림 (보유)
- [ ] B5 달 4장(보름달·그믐달·초승달·상현달, 검은 배경, 같은 크기와 위치). 상현달은 오른쪽 절반이 빛나는 반달, 그믐달은 왼쪽이 가느다략게 빛나는 달
- [ ] B6 출발 본 그림 + 까치를 지운 편집본 + 배경 없는 까치 **(필수)**

**C. 게임 안**

- [ ] C1 까치 옆모습, 날개 위·가운데·아래 3장 **(필수)**
- [ ] C2 까치 앉은 자세
- [ ] C3 타이틀 화면 (B4 재활용 가능)

## 수치

모든 수치는 `[SerializeField]`로 노출하고, 점프 수치는 솔버의 ‘1칸 점프’ 가정을 깨지 않는 범위 안에서만 조정한다.

| 항목 | 초기값 | 범위 | 이유 |
| --- | --- | --- | --- |
| 이동 속도 | 4칸/초 | 3\~5 | 퍼즐이 주라 정밀 조작 부담을 낮춘다 |
| 점프 높이 | 1.25칸 | 1.1\~1.4 | 1칸은 확실히 넘고 2칸은 못 넘게 |
| 점프 가로 거리 | 2칸 | 1.8\~2.4 | 1칸 틈은 건너고 2칸 틈은 못 건너게 |
| 중력 | 30칸/초² | 25\~40 | 떨어지는 느낌을 빠르게 |
| 회전 시간 | 0.35초 | 0.25\~0.5 | 공간 파악과 템포의 균형 |
| 회전 입력 버퍼 | 0.15초 | 0.1\~0.2 | 착지 직전 입력도 받는다 |
| 코요테 타임 | 0.08초 | 0.05\~0.12 | 플랫포머 관례. 억울한 낙하를 막는다 |
| 낙하 리셋 높이 | y < −3 | − | 은하수로 떨어진 것으로 본다 |
| 디더 내부 해상도 | 480×270 | 320×180\~640×360 | 거칠수록 목판 느낌, 고울수록 가독성 |
| Bayer 행렬 | 4×4 | 4×4 / 8×8 | 4×4가 패턴이 뚜렷하다 |

## 지표

핵심은 솔버가 자동으로 내는 설계 지표다. 플레이 지표는 클리어 로그 한 줄과 소규모 비교표만 만든다.

**설계 지표 (솔버, 사람 없이 자동)**

- 상태: (x, y, z, 시점 방향). 행동: 좌우 걷기, 1칸 올라가기, 1칸 틈 건너기, 낙하, 좌우 회전.
- BFS로 산출: 풀이 가능 여부, 최소 회전 수, 최소 행동 수, 탐색한 상태 수, 막다른 상태 비율.
- EditMode 테스트 하나로 ‘모든 구간이 풀리고, 최소 회전 수가 구간 구성 표의 범위 안’인지 확인한다. 구간을 고칠 때마다 품질 게이트가 잡아 준다.

**플레이 로그 (최소한)**

- 클리어할 때 `{level, rotations, jumps, time, resets}` 한 줄을 남긴다. WebGL에서는 마지막 결과 카드에 표시해서 테스터가 캐프처해 보내게 한다.
- README에 구간별 ‘최소 회전 수 / 실제 회전 수 / 효율’ 비교표 하나를 넣고, 그걸 근거로 고친 결정 한두 개를 적는다.

## 구현 메모

규칙 로직은 전부 순수 C#으로 두고 MonoBehaviour는 연결만 한다(ADR-0001). 그래야 솔버와 게임이 같은 규칙 코드를 쓰고 EditMode로 테스트된다.

| 클래스 | 종류 | 역할 |
| --- | --- | --- |
| `VoxelLevel` | ScriptableObject | 구간 그리드, 월드 위치, 입구, 까치 위치 |
| `ViewDirection` | enum | 4방향 시점 |
| `ProjectionMap` | 순수 C# | 시점별 3D → 2D 충돌 맵 |
| `Reprojector` | 순수 C# | 회전 시 깊이 재배치와 회전 거부 판정 |
| `PuzzleSolver` | 순수 C# | BFS, 설계 지표 산출 |
| `PlayerController2D` | MonoBehaviour | 충돌 맵 위 이동과 점프 |
| `ViewRotator` | MonoBehaviour | 카메라 회전 연출, 입력 잠금 |
| `DitherRenderFeature` | URP Renderer Feature | 풀스크린 디더링 |
| `LevelFlow` | MonoBehaviour | 글 카드, 클리어, 로그 |
| ZoneTracker | MonoBehaviour | 현재 구간 판정, 구간 밖에서는 회전 잠금 |
| CutscenePlayer | MonoBehaviour + ScriptableObject | 컷 목록(그림, 패닝, 시간, 문장, 디더 연출 값) 재생, 건너뛰기 |

하네스 이식: `game-designer`는 퍼즐 플랫포머용으로 바꾸고, `gameplay-programmer`에서 루트 모션·록온 줄을 빼고, 네임스페이스 `Soulslike`를 새 이름으로 바꾼다. 캐릭터 파일은 서브모듈인 `Assets/ThirdParty`가 아니라 `Assets/Art/Characters`에 둔다.

## 열린 질문

- [ ] **제목**: 칠석 / 오작 / 은하수 건너기. 추천은 ‘칠석’. 바로 알아보기 쉽다.
- [ ] **이동 방식**: 연속 이동(플랫포머 손맛) vs 칸 단위 이동(솔버와 1:1, 구현 쉬움). 추천은 연속 이동이고, 점프 수치로 솔버 가정을 지킨다.
- [ ] **회전이 막힐 때**: 거부(추천, 규칙 단순) vs 가장 가까운 빈칸으로 밀어내기.
- [ ] **프로젝트**: 기존 Project-Soul에 씬 추가 vs 새 프로젝트. 추천은 새 프로젝트에 하네스만 복사. 네임스페이스와 서브모듈이 섞이지 않는다.
