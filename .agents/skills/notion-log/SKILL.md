# 칠석 포트폴리오 기록

레포 기록을 원본으로 삼는다. [Codex 기록 규칙](https://app.notion.com/p/41e498d79c6881769c1cdbca957a3e99)의 「언제 기록하나」 표를 확인한다.

| 상황 | AI 작업 로그 | 결정 로그 |
| --- | --- | --- |
| 이슈를 마치고 PR을 생성했다 | 1건 | |
| 사람이 AI의 오류를 바로잡았다 | 반드시 1건 | |
| 사람이 AI의 제안을 거절했다 | 1건, 결과는 `폐기` | |
| 기획이 바뀌었다 | AI 작업이 기록할 만하면 1건 | `design/decisions.md`와 같은 내용으로 1건 |
| 범위를 줄였다 | | 1건, 종류는 `범위 축소` |

단순 수치 조정과 편집 수준 수정은 포트폴리오 로그에서 제외한다. 솔버가 발견한 의도하지 않은 지름길은 해당 구간 작업 기록에 풀이와 영향을 남긴다.

## AI 작업 로그

1. `production/ai-log.md`에 제목, 날짜, 단계, 도구(다중), AI가 한 일, 사람의 판단, 결과, 실패와 교훈, 역량(다중), 근거를 적는다. AI가 한 일과 사람의 판단은 구분한다. 사람의 판단은 사용자가 채팅에서 실제로 한 발언을 바탕으로 쓰고, 애매하면 초안을 보여 주고 확인을 받은 뒤 게시한다. 실패와 교훈에는 관찰한 사실을 한두 문장으로 쓴다. 근거는 실제 PR·커밋·이슈 URL을 사용한다.
2. Notion에서 `collection://41e498d7-9c68-810b-8d35-000b1da92fdd`를 조회해 현재 필드와 선택값을 확인한다. 같은 근거의 동일 사건이 이미 있으면 해당 기록을 사용한다. 게시가 확인되면 레포에 Notion 링크를 붙이고 `노션 반영됨`을 표시한다.
3. Notion에 쓸 수 없으면 동일한 칸으로 저장한 레포 항목을 `노션 반영 대기`로 둔다. 다음에 연결되면 기존 항목을 확인하고 옮긴 뒤 `노션 반영됨`으로 바꾼다.

## 결정 로그

`AGENTS.md`의 기획 변경 절차에서 `design/decisions.md`를 먼저 갱신한다. 날짜, 변경 내용, 이유, 영향을 `collection://41e498d7-9c68-8105-a704-000b103fe716`에 옮기고, 확인 가능한 종류, 제안한 쪽, 상태, 근거를 덧붙인다. Notion에 쓸 수 없으면 레포 결정은 유지하고 어느 항목이 반영 대기인지 인수인계에 적는다.
